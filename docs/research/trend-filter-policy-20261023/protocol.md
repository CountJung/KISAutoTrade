# P2-11 추세 필터 사전 설계

이 문서는 새 후보 손익 실행 전의 연구 계약이다. [기계 판독 설계](design.json)를 고정하며 새 후보 결과는 아직 없다. 이미 본 과거 자료의 재분석이므로 미관측 OOS 사전 등록이나 실운용 검증으로 표현하지 않는다. 기존 SOXQ-P2-11은 열린 상태로 유지한다.

## 기준 구현과 결정 순서

기준 커밋은81fa00d3aa50bc59606667568f36c4b686902412, 생산 엔진은strategy-replay-v21이다. 새 구현의 예정 엔진은strategy-replay-v22이며 실제 버전은 구현과 실행 뒤 확인한다. 기준 mean_trend.rs의 TrendFilterParams/TrendFilterStrategy와 생산 strategy_preview/driver.rs::run_prepared_preview를 Serena로 확인했다. 별도 신호 모델을 작성하지 않고 실제 Rust 전략·회계를 호출한다.

원래 long_period200/short_period5/mid_period20과 현재 가격을 먼저 적재하는 산술평균을 유지한다. 진입은 실제 미보유에서 price > longMA AND shortMA > midMA, 원래 청산은 실제 보유에서 price < longMA다. 등호는 해당 진입/청산 조건에 포함하지 않는다. shortMA <= midMA만으로 청산하지 않으며 별도 원가 손절은 없다. 원래 장기 추세 이탈 청산을 새로운 기능으로 중복 추가하지 않는다.

기존 구현은 신호 제안으로 in_position을 바꾸고 sync_position에서 실제 수량과 평균가를 bool로 축약한다. 소유 교정과 선택 청산 정책의 손익 효과를 구분한다. legacy와 owned 결과가 같을 것이라고 미리 가정하지 않는다. 기존 live bool 복원·driver sync와 공통 수량 clamp/guard도 존재하므로, 이 소스 표현의 한계만으로 실제 초과매도·운용 사고·기존 손실 원인을 단정하지 않는다. 설정7주·실보유2주의 기존 매도 제안 fixture 통과는 현재 동작을 고정하는 회귀이며 새 실잔량 교정 완료가 아니다.

원래 MA 이탈 청산은 long/mid/short 세 MA가 모두 준비되는 기존 gate를 유지한다. 비정렬 기간이나 기간 확대에서 장기 MA만 준비되면 원래 청산을 허용하는 변경은 이번 범위에 넣지 않는다. 새 수익/보유 나이 보호는 이 gate와 독립적으로 실제 보유를 평가한다.

## 고정 후보와 상태 계약

| 후보 | 기준 | 단독 변경 | 해석할 위험 |
|---|---|---|---|
| legacy | 직전 커밋 생산 구현 | 없음 | 기준 경로 |
| owned | 실제 수량/native 평균·실잔량 청산 | 선택 정책은 기본값 | 정확성 교정과 경제 경로 차이를 분리 |
| exit2 | owned | exit_confirm_observations=2 | 회전 감소 가능성·이탈 청산 지연·손실 확대 |
| profit5trail3 | owned | profit_activation_pct=5, profit_trailing_pct=3 | 이익 실현 가능성·강한 추세 조기 종료·재진입 비용 |
| hold63 | owned | max_hold_observations=63 | 장기 평가수익 의존 감소 가능성·강제 청산·회전 비용 |

기본 확인 횟수는1이며0으로 원래 청산을 끄지 않는다. 수익 보호 쌍과 보유 한도만 기본0off다. 이탈 확인은 실제 보유 중 현재 포함 MA에 대한 strict price < longMA의 연속 관측이다. price >= longMA 또는 유효 MA 부재에서는 연속값을0으로 한다. 확인 이후 이탈이 지속하면 거절/부분매도 뒤에도 실잔량 후보를 유지한다. 같은 가격의 후속 quote도 원래 관측 주기의 관측이며 일별 확인으로 바꾸지 않는다.

실제 수량/native 평균은 확인된 체결·소유 feedback만 바꾼다. 신호·pending·거절·부분매도는 소유를 위조하지 않고 물리 pending 중 새 진입 기원을 만들지 않는다. 실제 첫 fill의 보유 나이는0, 다음 보유 관측은1이며 off 중에도 센다. 출처 없는 positive 복원은 unknown이고 활성 한도에서는 다음 보유 관측에 보수적 잔량 청산 후보다. 동일 수량·부분매도·선택 정책 변경은 실제 보유 나이/최고가/무장을 보존한다.

수익 보호는 실제 native 평균에서5% 상승하면 한번 무장하고 실제 보유 관측 최고가에서3% 되밀림을 확인한다. 진입 전 가격이나 해당 일봉 전체 high를 보유 최고가로 사용하지 않는다. 기존 장기 이탈 확인→수익 보호→보유 한도 순서를 고정한다. 관측 보호는 다음 관측/다음 시가 가정이므로 장중 손실 상한이나 체결 가격 보장이 아니다.

확인 연속값은 영속 checkpoint로 이식하지 않는다. 복원 시0으로 시작하여 새 MA 문맥에서 다시 관측한다. 실제 보유 나이/최고가/수익 무장 checkpoint와 분리한다. 동일 프로세스의 청크 분할·동일 수량·부분매도에서는 이탈 연속값을 보존한다. warmup 재초기화·과거 지표 재적재·핵심 long/short/mid 변경·reset 또는 실제0주 전환은 연속값0이다. 동일 설정이나 선택 정책만의 변경은 보유 보호를 보존한다. warmup으로 신호·소유·보유 나이·최고가·무장을 만들지 않는다.

소유 checkpoint의 정확한 kind/version/필드는 구현 전에 확정한다. 누락·미지 필드·다른 kind·모순된 나이/최고가/무장을 원자적으로 거부하는 완료 조건을 둔다. 오래된 MA 문맥의 확인 횟수를 소유 증거와 함께 복원하지 않는다. 엄격 raw 값 범위와 손상 runtime 처리의 세부 사항은 구현 결정으로 남기되, 잘못된 새 필드가 유효한 기존 설정을 전체 기본값으로 덮거나 보호를 조용히 끄지 않게 검증한다.

## 실행·감사와 객관적 완료 조건

부모가 기준 커밋의 생산 라이브러리를 격리하고 현재 생산 Rust API에 연결한 연구 harness를 실행한다. 별도 전략 신호 모델이나 과거 신호의 다른 체결 모델 재사용은 금지한다. 실제 engineVersion·inputHash·소스와 runner hash·경제 가정·생성 원장을 기록한다. 이미 본 과거 구간이며 선언 이후 새 후보 결과를 보고 임계값·창·수량·조합을 바꾸지 않는다.

- [ ] 기본200/5/20·현재 포함 산술 MA·strict 경계·원래 청산과 기본 확인1을 검증한다.
- [ ] 실제 수량/native 원가·잔량·미체결 기원·거절/부분/동량·기원 미상·재설정/복원·확인값0계약을 검증한다.
- [ ] 준비 부족에서도 유효 보유 보호를 평가하고 미래prefix·단일/분할 공급 불변을 검증한다.
- [ ] 새 설정 저장/두preview/UI/current/A-B·불법raw·모바일을 실제 fixture/mock으로 확인한다.
- [ ] 기준 구현/비대상 회귀와30연속/30분할/360별도분기의 결과를 수집한다.
- [ ] 순수익·시장가격 경로 참조·MDD·완료 거래/손실·실현/미실현/잔여·기말 가상 청산 비용·차단·노출·회전·준비/미발동을 독립 대사한다.
- [ ] 같은 요청 수량 보유 비교의 실제 체결량/노출을 확인하고30%제한의0주를 동일노출 초과수익으로 취급하지 않는다.
- [ ] 마지막 pending 미체결·기말 수량/native평균/역사원가/매수fee를 기록하며 가상 청산을 실거래에 합산하지 않는다.
- [ ] 검증/코드 리뷰/지도·문서 게이트 뒤 기존P2-11만 갱신하고 검증된 변경을 커밋·푸시한다.

동일 accepted 수량/보유 구간의 close→open gap과open→close 시장손익을 고정FX로 대사한다. 이 값과 기록 비용 환급 참조를 비교하되 독립alpha benchmark·같은%노출·무비용 전략 재실행으로 표현하지 않는다. 이익 보유분의 잔여 평가수익과 손실 완료 거래를 따로 해석한다.

준비 부족·미지원은 평가 불가이며 미발동 후보의 효능도 미평가다. 완료 표본이 작거나 단일 종목/비용에서 좋아도 기본 승격 근거가 아니다. 반복한 과거 실행·상관된ETF·겹치는 기존45창과 이번12분기를 독립OOS로 합치지 않는다. 실제 주문·계좌·자동매매·provider 인증·운영 설정은 다루지 않는다. 이 기록의 준비 완료와P2-11 구현/연구 완료는 구분한다.
