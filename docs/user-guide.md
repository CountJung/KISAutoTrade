# KISAutoTrade 사용 가이드

KIS와 Toss 계좌를 같은 화면에서 관리하는 개인용 주식 매매 앱입니다. 이 문서는 2026-10-18 현재 저장소의 UI·명령·adapter 구현을 기준으로 합니다. 구현 지원과 실제 계좌·provider 응답 검증을 구분하며, 잔여 검증은 [할일](todo.md)에서 확인합니다.

## 1. 시작하기

설치·개발·패키지 빌드는 [README](../README.md#설치와-개발)를 참고하세요. 계좌 연결 후에는 먼저 조회 진단을 확인합니다. **전략 설정 저장**, **전략 카드 ON**, **자동매매 시작**은 별도 동작입니다. 시작 버튼을 누르면 활성 전략이 실제 주문을 낼 수 있습니다.

| 화면 | 주요 기능 |
|---|---|
| Dashboard | 활성 계좌·자동매매 상태, 잔고·보유종목, 리스크·매수 정지, 환율·당일 통계 |
| Trading | broker에 맞는 종목 검색·시세·차트, 수동 매수·매도, Toss 사전검증·접수 주문 |
| Strategy | 13개 전략 카드, 종목·파라미터·ON/OFF, 미리보기·성과 분석·A/B 기록 |
| History | 기간별 앱 거래·통계와 증권사 체결 조회 |
| Log | 로그 레벨·키워드 조회, 오류 원인 확인 |
| Settings | 프로파일, 리스크, 자동매매 예산, API 호출 제한, 웹·저장소·로그·알림 설정 |

## 2. Broker별 지원 범위

| 항목 | KIS | Toss |
|---|---|---|
| 프로파일 | APP KEY/SECRET, 계좌번호, 실전·모의 | Client ID/Secret, `accountSeq`, 실거래 동의 |
| 연결 확인 | 설정 진단·실전/모의 자동 감지 | 연결 진단·계좌 목록 조회; KIS 자동 감지 사용 안 함 |
| 가격·잔고 | 국내·미국 가격·잔고 | 국내·미국 가격·보유종목·잔고 |
| 추가 시세 | KIS 조회 경로 | 호가, 최근 체결, 가격 제한·종목 안전 정보 |
| Trading 국내 주문 | 지정가·시장가 | 지정가·시장가 |
| Trading 미국 주문 | USD 지정가 | USD 지정가와 거래 세션 선택 |
| 자동매매 | KIS 가격·과거 자료·주문 adapter | Toss 가격·캔들·주문 adapter; 실거래 동의 필수 |
| 자동매매 시세 처리 | REST 폴링; KIS WebSocket 보조 | REST 폴링; KIS 키·WebSocket으로 대체하지 않음 |
| 차트 자료 | 국내·미국 일/주/월봉 조회 | 일봉(`1d`)·1분봉(`1m`) |
| 세션 판단 | 앱 시간 gate와 provider 오류 응답 | provider 달력 및 미국 세션 정책 |
| 모의투자 | 별도 모의 프로파일; 해외 종목·거래소·조회 조건 제한 가능 | 앱에 모의투자 모드 없음 |

표의 주문 지원은 현재 **화면에서 선택할 수 있는 범위**입니다. adapter나 별도 IPC의 지원이 더 넓어도 화면에서 제공하지 않는 주문 유형을 사용 가능으로 보지 않습니다. 계좌 권한·휴장·종목별 허용 여부는 실제 provider 응답이 결정합니다.

## 3. 계좌 프로파일

### KIS 추가·전환

1. Settings → 계좌 프로필 → **계좌 추가**에서 KIS를 선택합니다.
2. 프로파일 이름, APP KEY, APP SECRET, 계좌번호, 실전/모의 모드를 입력합니다. 계좌번호는 10자리 또는 `앞 8자리-뒤 2자리` 형식을 사용합니다.
3. 필요하면 **실전/모의 자동 감지** 결과를 확인하고 저장합니다.
4. 프로파일을 활성화한 뒤 설정 진단과 Dashboard 잔고를 확인합니다.

키 발급·권한 관리는 [KIS 공식 포털](https://apiportal.koreainvestment.com/)에서 진행합니다. 모의/실전 키와 프로파일 모드를 일치시킵니다. 모의투자의 해외 조회·매도 제한이 표시되면 오류를 숨기거나 실전으로 자동 전환하지 않습니다.

### Toss 추가·전환

1. 계좌 추가에서 Toss를 선택하고 **Client ID**, **Client Secret**을 입력합니다.
2. **계좌 목록 조회**를 실행하고 마스킹된 계좌 목록에서 사용할 `accountSeq`를 선택합니다. 계좌번호를 `accountSeq` 대신 직접 넣지 않습니다.
3. 프로파일을 저장·활성화하고 카드의 **연결 진단**으로 스펙·인증·계좌·잔고 조회 결과를 확인합니다.
4. 실제 주문을 사용할 때만 프로파일 편집에서 **실거래 동의**를 저장합니다. 연결 진단 성공 자체는 실거래 동의가 아닙니다.

Toss는 [공식 Open API](https://developers.tossinvest.com/docs)를 사용합니다. 비공식 웹 로그인·쿠키·WTS 세션을 연결하지 않습니다. KIS용 실전/모의 자동 감지에 Toss Client ID/Secret을 넣지 않습니다.

### 활성 계좌와 실행 계좌

계좌 전환 뒤 Settings/Sidebar의 **활성 broker/account**를 확인합니다. 실행 중인 자동매매는 시작 시점의 **실행 broker/account**를 따로 보관합니다. 프로파일만 바꾸어 주문 계좌가 변경되었다고 판단하지 말고 자동매매를 정지한 뒤 계좌·전략·미체결을 확인하고 다시 시작합니다. 전략 설정은 프로파일별로 관리합니다.

계좌를 전환하면 국내·해외·브로커 보유 화면은 새 계좌의 조회를 기다립니다. 이전 계좌의 늦은 응답이나 백그라운드 이벤트로 보유 목록을 채우지 않습니다. 조회 중 체결·새 조회·설정 저장·실행 상태 변경이 겹치면 해당 응답이 보류될 수 있으므로 현재 계좌를 확인한 뒤 다시 조회하세요. 새 계좌 설정을 확인하지 못하면 이전 잔고를 현재 계좌 자료로 표시하지 않습니다. 증권사 자체의 잔고 반영 지연까지 제거하는 기능은 아닙니다.

## 4. 수동 거래와 주문 확인

1. Trading에서 활성 broker와 국내/미국 시장을 확인합니다. KIS 국내 코드는 6자리 영숫자(예: `005930`, `0005A0`)이며 미국은 검색한 ticker와 거래소를 확인합니다.
2. 종목·매수/매도·수량을 입력하고 지정가이면 가격을 입력합니다. 미국 가격은 USD로 표시합니다.
3. Toss는 실거래 동의와 **주문 전 사전검증**을 통과해야 제출할 수 있습니다. 가능금액·매도가능수량·통화·종목 안전 상태·차단 사유를 확인합니다.
4. 주문 제출 후 주문번호와 미체결·부분체결·완전체결 상태를 확인합니다. 접수 성공 메시지는 체결 완료를 뜻하지 않습니다.

### Toss 미국 세션

Trading은 **자동 / 주간 / 프리 / 정규 / 애프터**를 제공합니다. 세션을 지정하면 provider 달력의 해당 시간과 현재 개장 상태를 검사합니다. **자동**은 세션을 지정하지 않고 provider의 주문 접수 판단을 따릅니다. 화면의 날짜·세션 시간을 확인하고 고정 KST 시간만으로 거래 가능 여부를 판단하지 않습니다.

Toss 접수 주문 목록에서는 상태를 조회하고 허용된 주문의 정정·취소를 요청할 수 있습니다. 미국 주문 정정은 UI에서 수량 변경이 제한됩니다. 자동매매 예산 주문은 정정이 차단되므로 취소 후 새 주문을 사용합니다. 취소 요청 뒤에도 provider 최종 상태를 확인합니다.

### 소액 실거래 검증

Dashboard의 **Toss 소액매매 검증** 패널은 실거래 동의 상태와 Trading 이동 경로를 안내합니다. 현재 패널에서 별도 1주 주문을 즉시 제출하지 않습니다. Trading의 일반 수동 주문은 사용자가 입력한 수량과 사전검증을 사용하므로 **자동으로 1주·소액 한도가 적용된다고 가정하지 않습니다**.

별도 소액 검증 IPC는 명시적 확인, 1주, 최대 허용금액, 미체결 충돌 검사를 갖추고 있지만 일반 Trading 폼과 다른 경로입니다. 실제 주문·취소·부분체결 검증 기록은 모의 응답 테스트와 구분합니다. 문서·시뮬레이션 작업이 실거래 검증 실행을 대신하지 않습니다.

## 5. 전략 설정과 미리보기

Strategy의 카드에서 대상 종목·수량·파라미터를 수정하고 저장합니다. 각 전략의 보유는 그 전략이 제출한 주문의 확인된 체결로 관리합니다. 같은 종목의 다른 전략·수동 보유를 가져오지 않으며 실제 계좌 수량과 공통 주문 제약은 함께 확인합니다.

설정은 저장이 성공한 뒤 적용됩니다. 같은 전략·계좌에서 유지한 종목의 보유 기준과 LTH 최고가·보유 관측 수를 보존하며 새 파라미터를 적용합니다. 저장 실패 시 기존 설정과 보유 보호를 유지합니다. 원본 설정 복구까지 실패하면 저장 오류를 표시하고 신규 주문을 차단합니다. 저장 중에는 해당 계좌의 새 전략 신호를 잠시 보류하고 완료 후 재개합니다.

신호나 해당 종목의 제출·미체결·정정 주문을 처리 중이면 저장이 거부될 수 있습니다. 주문 상태를 확인한 뒤 다시 저장하세요. 보유 중이거나 전략이 보유 보호 상태를 유지하는 종목은 대상에서 제거하거나 국내·해외 구분을 바꿀 수 없습니다. 실제 보유와 미체결을 확인하고 포지션을 정리한 뒤 변경합니다. 새 대상 종목에 다른 전략이나 수동 주문의 보유를 자동 배정하지 않습니다. 저장 요청을 보낸 뒤 화면을 닫아도 이미 시작한 저장은 완료될 수 있으므로 다시 열어 현재 설정을 확인하세요.

| 카드 / 전략 ID | 판단 요약 |
|---|---|
| 이동평균 교차 / `ma_cross` | 단기·장기 이동평균 교차 |
| RSI / `rsi` | 과매도 반등·과매수 약화 |
| 모멘텀 / `momentum` | 이전 가격 대비 변화율 |
| 이격도 / `deviation` | 이동평균 대비 가격 괴리 |
| 52주 신고가 / `fifty_two_week_high` | 과거 범위 고점 돌파·손절 |
| 연속 상승/하락 / `consecutive_move` | 연속 관측 가격 방향, 선택적 누적 변화·ATR·장기 MA 진입 확인 |
| 돌파 실패 / `failed_breakout` | 이전 고점 돌파 후 실패 |
| 강한 종가 / `strong_close` | 완료일의 강한 마감 조건 |
| 변동성 확장 / `volatility_expansion` | 이전 완료 범위 대비 변동폭 확대 |
| 평균 회귀 / `mean_reversion` | 평균·표준편차 밴드 |
| 추세 필터 / `trend_filter` | 장·중·단기 이동평균 조건 |
| 가격 조건 / `price_condition` | 종목별 매수가·익절가/비율·손절 조건 |
| 레버리지 추세 보유 / `leveraged_trend_hold` | 선택 ETF의 추세·반동 진입과 수익 보호·청산 |

기간 값의 단위는 입력된 **관측/봉**입니다. 시작 시 과거 자료를 적재하지만 live 가격 폴링과 일봉 replay는 같은 시계열이 아닙니다. 예를 들어 MA 20을 항상 20일 또는 항상 200초로 바꾸어 설명할 수 없습니다. 준비 자료 수·평가 가능 상태·실제 신호 수를 따로 확인합니다.

### 일반 전략 미리보기

활성 프로파일과 종목·기간·평가 구간을 확인하고 미리보기를 실행합니다. 지원되는 일반 전략은 과거 사전자료와 평가 구간을 분리하고 비용·환율·리스크 가정에 따른 성과·단순 보유 비교·신호·차단 사유를 제공합니다. A/B 기록은 해당 설정과 replay metadata를 함께 보관합니다.

단기 구간 미리보기는 선택 계좌의 완료봉을 순차 조회해 평가50/100/200봉과 그 이전252봉을 분리합니다. 최대8회 요청·보관500봉이며 실제 확보량·출처·중복/미완료/무효 제외 수·중단 사유를 표시합니다. 부족하다고 요청 평가 구간을 사전자료로 옮기지 않습니다. 조회 중 취소하거나 계좌·종목·파라미터를 변경하면 이전 결과를 폐기합니다. 당일/이번 주/이번 달은 보수적으로 제외하고, Toss 분봉은 봉 종료 시각을 사용합니다. 이것이 전용 LTH의 3개월 장중 검증을 대신하지는 않습니다.

**계산 범위 모드 → 연속 일봉·날짜 범위**를 선택하면 기본으로 어제까지 최근3년을 요청합니다. 시작일 이전252개의 완료 일봉을 한 번 준비한 뒤 같은 자본·수량 규칙으로 전 기간을 이어 계산합니다. 페이지/공급 묶음·분기 경계에서도 보유·원가·대기 신호·쿨다운·리스크를 초기화하지 않습니다. 단기50/100/200봉 모드와 LTH 전용 표본 경로는 별도로 유지됩니다.

연속 수집은 최대48회 요청·보관4608봉·평가4096봉으로 제한됩니다. 요청/실제 관측 범위, 이전 자료 확보량, 조회 기준 시각, 제외/중복 수와 중단 사유를 확인하세요. 시작 이전252봉이나 요청 범위를 확보하지 못하면 계산을 보류합니다. 요청/실제 시작·종료 차이 또는 관측 사이 간격이7달력일을 초과해도 보류합니다. 이 기준은 앱의 보수적 자료 경계라 긴 휴장도 보류할 수 있으며 거래소 달력 검증을 뜻하지 않습니다. 준비 완료에도 `coverageVerified=false`로 표시하고 누락 봉을 만들지 않습니다. 과거 일부 자료만 있는 결과를 최근3년 전체 성과로 해석하지 마세요.

연속 결과의 공급 경계 표는 묶음 전후 보유와 다음 봉까지 보존한 대기 신호를 보여줍니다. 앞/뒤 구간70/30은 같은 장부의 관측 구분이며 독립 훈련·검증이 아닙니다. A/B에는 계산 모드와 경계 정보도 보관하며 이전 슬롯에 모드가 없으면 정보 없음으로 표시합니다. 날짜·모드 변경이나 취소는 진행 결과를 폐기합니다. 세부 상한과 입력 형식은 [v12 IPC 계약](ipc-commands.md)을 참조하세요.

**백테스트 ATR 기반 수량 산정**은 연구 전용 실행 가정이며 기본 비활성입니다. Settings의 실운영 리스크 설정과 별도로 적용됩니다. 활성화하면 이전 종가와 갭을 포함한 TR 14개가 필요하므로 같은 간격의 관측 15봉부터 준비됩니다. 준비 부족·변동폭 0·위험 예산 0bps에서는 신규 매수를 차단하며 보유 매도는 유지합니다. 전략의 준비 상태와 ATR의 시작·종료 준비, 미준비 평가봉 수를 따로 확인하세요. LTH의 일봉 context는 분봉 ATR을 준비하지 않습니다.

**체결 모델**에서 기존 **같은 봉 종가** 또는 **다음 관측 봉 시가**를 선택합니다. 후자는 종가 신호를 다음에 확보된 봉의 시가에서 비용·현금·리스크 조건에 맞춰 처리하고, 그 원가를 이후 전략 판단에 반영합니다. 마지막 신호 뒤 봉이 없으면 **미체결**로 표시합니다. 같은 종가 모델은 종가 공개 후 그 가격에 체결할 수 있다는 낙관적 가정입니다. 신호 확인/체결의 봉과 단계는 정확한 거래소 체결 시각과 구분해 읽으세요.

**연구 손절·익절**의 0은 비활성입니다. 실제 진입 원가에 대한 별도 연구 시나리오로, 전략 자체의 청산 규칙과 Settings의 실운영 리스크를 바꾸지 않습니다. **봉 내부 미검증**은 고저가 접촉만으로 청산하지 않고, **손절 우선 가정**은 순서가 불명인 동시 도달을 손절로 처리하며 경고를 남깁니다. 시가 갭은 관측 시가에서 처리하므로 지정 손절률이 손실 상한이라는 뜻이 아닙니다. 수수료·슬리피지와 열린 보유를 포함한 모의 결과이며 실제 호가·유동성 검증은 아닙니다. A/B에는 엔진과 체결 가정도 함께 표시합니다.

**비용 출처와 현금흐름**에서는 추정 비용 또는 브로커 조건의 사용자 수동 확인을 선택합니다. 수동 확인에는 최대 120자의 출처 메모가 필요하며 앱의 자동 요율 검증을 뜻하지 않습니다. 매수·매도 수수료를 따로 입력하거나 비워 공통 수수료를 사용할 수 있고, 체결당 최소 수수료는 국내 원·해외 USD 단위입니다. 실제 계좌 할인·환전 비용·해외 양도소득세는 별도로 확인하세요.

FX·배당 JSON은 각각 최대 64개의 실제 평가 봉을 지정합니다. 국내 FX는 허용하지 않으며 잘못된 JSON·중복 시각·누락 봉은 빈 시나리오로 처리하지 않습니다. 잘못된 입력은 기존 결과를 폐기하고 계산을 막습니다. 환율은 지정 봉부터 이후로만 적용하며 유휴 현금은 원화로 유지합니다. 배당은 해당 봉 직전 보유 수량에 세후 현금을 지급하는 연구 가정으로 실제 배당락·지급일을 대체하지 않습니다. **가격 자료의 배당 반영**은 사용자 선언입니다. 배당 조정 가격에 현금 배당을 더하는 입력은 거부하며 미확인은 경고합니다.

**손익과 현금흐름 분해**에서 실현손익·잔여 평가손익·순배당을 구분해 전체 자산 증감과 함께 확인하세요. 실현 이익이어도 잔여 평가손실로 전체 수익률은 음수일 수 있습니다. 가격/환율 효과, 수수료·거래세·슬리피지 영향과 청산 표본 수도 따로 표시합니다. **종료 시 가상 청산**은 남은 보유를 매도한다고 가정한 참고값이며 실제 체결 수·승률에 더하지 않습니다. **봉말 평균 보유 평가액**과 초기자본/당시 자산 대비 관측 평균·최대 비중은 보유 봉 비율과 다르고 실제 시간으로 가중한 노출도 아닙니다.

**단순 보유 비교**는 같은 입력 수량을 사용하지만 실제 진입 수량과 투자 비중이 달라질 수 있습니다. **동일 체결 경로 비용 제거 참고값**은 실제 계산의 수량·시점·노출을 고정한 원화 비용 환급 산술이며 무비용 전략을 다시 실행한 성과가 아닙니다. A/B에는 이러한 가정과 서버 집계를 보관합니다. 이전 결과에 손익 분해가 없으면 0으로 추정하거나 잘린 거래 목록에서 복원하지 않습니다. 겹친 기간의 비교·소표본은 독립 검증이 아니고 부분기간을 전체 분기·연속 성과로 합산하지 마세요. 입력 범위와 회계식은 [상세 IPC 계약](ipc-commands.md), 검증 범위는 [Harness 지도](HARNESS_MAP.md)를 참조하세요.

52주 신고가의 일봉 replay는 완료 고가 252봉을 보관하고 오래된 고가를 만료합니다. live는 실행 계좌와 시장 날짜를 고정한 백그라운드 조회로 완료 일봉을 갱신합니다. Dashboard/Strategy의 **실시간 전략 일봉 준비**에서 실제 확보량·마지막 완료일·실패와 재시도를 확인하세요. 준비 중/부족/실패는 신규 진입을 보류하고 보유 손절은 유지합니다. 마지막 봉이10일을 초과해 오래되면 긴 휴장도 보수적으로 보류합니다. [구현·검증 범위](tasks/live-completed-daily-history-20261018.md)를 실제 provider 운용 검증과 구분합니다.

강한 종가·변동성 확장의 일반 replay는 일봉(`D`/`1d`)을 지원합니다. 신호는 완료 일봉 종가에서 판단하고 체결은 선택한 실행 가정에 따릅니다. 장중 고저가 순서·지연·실제 주문 체결을 재현하지 않습니다. 신호가 없거나 사전자료가 부족한 결과를 전략 수익성 검증 완료로 보지 않습니다.

### LTH 전용 편집과 평가 상태

레버리지 추세 보유는 기존 카드의 전용 편집창을 사용합니다. generic replay에 LTH를 넣으면 지원하지 않는 경로로 거부합니다. 선택한 롱·숏 ETF 자체를 같은 추세 논리로 처리하며 자동 인버스 전환 기능을 뜻하지 않습니다.

- **일봉**: 일봉 context 자료 진단이며 장중 진입·청산을 합성하지 않습니다. FX/배당 시나리오도 계산할 수 없어 비어 있지 않은 입력을 거부합니다. **성과 평가 불가**로 표시하고 수익률·승률·A/B 성과 저장을 제공하지 않습니다.
- **1분봉**: 현재 최대 200봉의 장중 **표본**입니다. 유효 관측이 없으면 평가 불가입니다. 시간대·DST·세션 검증은 미완료로 표시하며 3개월 성과로 확대 해석하지 않습니다.
- 일봉 context와 분봉 EMA·RSI·ADX·반동·볼린저 버퍼는 분리합니다. 일봉 자료만으로 분봉 지표 준비가 끝나지 않습니다.
- **볼린저 스퀴즈·추세 돌파 보강**은 같은 전략의 선택 옵션이며 기본 비활성입니다. 필요한 분봉이 부족하면 진입을 보류합니다. 상단 터치만으로 청산하지 않고 기존 수익 보호에 중심선·ATR 조건을 보강합니다.

실제 3개월 SOXQ 분봉과 거래소 시간·세션 검증은 [P1-05 기록](tasks/soxq-p1-05.md)에 남아 있습니다. [전략 전수 분석](research/strategy-review-20261018/report.md)은 비교 연구 근거이며 특정 종목·파라미터의 추천 목록이 아닙니다.

## 6. 자동매매와 리스크

Settings에서 손실 한도·종목 비중·연속 손실 차단·매도 횟수·선택적 ATR 수량 조건을 확인합니다. Dashboard는 비상정지·매수 정지·보류 사유를 표시합니다. 한도는 계좌와 운용 판단에 따라 사용자가 결정합니다.

시작 전 활성 프로파일과 전략을 확인하고 **자동매매 시작**을 누릅니다. 백엔드는 broker 잔고·포지션, 계좌 평가액, 복원된 미체결, 당일 리스크 상태를 확인하고 시작 계좌를 고정합니다. 확인 실패로 시작이 차단되면 오류를 먼저 해결합니다. 시작 뒤 과거 자료를 준비하고 시장 gate를 통과한 종목의 현재가를 폴링합니다. KIS WebSocket이 끊겨도 폴링 루프는 별도로 동작합니다.

정지·재시작이나 전략 설정 변경 전에 생성된 신호는 실행 식별자를 확인해 폐기합니다. 자동매매는 시작 때 검증한 계좌와 연결 정보를 유지하며, 정지 전에 이미 예약한 주문은 같은 계좌로 제출·재시도·기록될 수 있습니다. 정지는 예약·미체결 주문을 취소하는 기능이 아니므로 주문 이력을 함께 확인합니다. 비활성 프로파일 삭제는 현재 실행에 영향을 주지 않습니다. 활성 KIS 프로파일의 실전/모의 자동 감지는 자동매매를 정지한 뒤 실행합니다.

체결과 부분 체결은 주문을 낸 전략의 확정 수량에 반영합니다. 잔고 조회가 그 체결을 이미 포함해도 수량을 다시 더하거나 빼지 않습니다. 체결 뒤 해당 시장의 잔고를 다시 확인하는 동안 새 주문은 보류될 수 있습니다. LTH의 최고가와 보유 관측 수는 정상 체결·재시작 때 평균가 기준으로 초기화하지 않습니다.

Toss 주문 전 검증의 수수료율은 공식 비율을 퍼센트로 표시합니다. 예를 들어 원본 `0.00015`는 `0.015%`입니다. 필요 현금에는 이 비율로 추정한 수수료를 포함하므로 주문금액만큼의 현금이 있어도 부족으로 표시될 수 있습니다.

도입 이전 보유나 원가·투자모드를 확인할 수 없는 기록은 임의로 전략에 배정하지 않습니다. 체결 소유 원장 누락·손상 또는 리스크 복원 오류가 표시되면 신규 주문을 차단합니다. 파일 삭제나 이전 백업 덮어쓰기로 해제하지 말고 증권사 체결과 원본 기록을 대조해야 합니다.

다른 계좌나 투자 모드의 미체결은 보존하고 해당 계좌·모드를 다시 선택했을 때 대조합니다. KIS 미체결의 저장 기록에서 투자 모드를 확인하지 못하면 추정해 반영하지 않고 계좌 동기화 상태에 보류 사유를 표시합니다. 이 경우 기존 기록을 삭제해 차단을 우회하지 말고 증권사의 주문 내역과 대조합니다.

KIS 시장 gate는 국내 평일 장중·미국 야간 시간 근사와 provider 응답을 사용합니다. Toss는 provider 달력과 전략의 미국 세션 정책을 사용합니다. 이 live 운용 gate가 LTH replay의 DST·거래소 시각 검증 완료를 뜻하지 않습니다.

전략 신호는 scope 확인 → 주문 전 검증 → 리스크/반복 주문 방어 → pending 충돌 예약 → broker 제출 → 주문/체결 저장·대조를 거칩니다. 비상정지나 저장 실패로 주문이 차단된 상태를 파일 삭제·재시작으로 우회하지 않습니다. 정지 후에도 이미 접수된 주문이 증권사에서 자동 취소되었다고 가정하지 말고 미체결을 확인합니다. 비상정지 해제는 원인과 계좌 상태를 확인한 뒤 사용자가 실행합니다.

## 7. 자동매매 전용 예산

Settings → **자동매매 전용 예산**에서 선택 계좌의 KRW·USD 배정액을 저장합니다. 자동매매 정지 상태에서 변경하며 초기 배정액은 0입니다. 실제 계좌 이체나 증권사의 자금 잠금이 아니라 앱의 자동 주문 한도입니다.

자동매수는 지정가와 비용 여유분을 먼저 예약합니다. 현재 예산 장부는 매수·매도 체결금액의 1%를 보수적 비용으로 반영하며 실제 수수료 명세와 다릅니다. 매도 대금은 비용 차감 후 전용 현금으로 돌아옵니다. KRW와 USD는 서로 사용하지 않습니다.

수동 매수·도입 이전 보유분은 자동매매 소유분에 편입하지 않습니다. 자동매도는 장부의 자동매매 수량까지만 가능하며 앱 수동 매도도 자동 소유수량을 제외합니다. 보유·미체결 예약에 묶인 금액은 인출할 수 없습니다.

배정액·현금·예약액·사용 가능액·보유 종목 수·보류 사유는 Settings에서 확인합니다. 응답 불명 주문이나 원장 오류는 예약·예산을 보류합니다. 원장을 삭제하거나 과거 백업으로 덮어쓰지 말고 증권사 주문번호·체결 내역을 대조해야 합니다.

## 8. 저장과 DB 전환

| 자료 | 위치와 경계 |
|---|---|
| 계좌 프로파일 | OS 앱 데이터의 `com.countjung.kisautotrade/profiles.json` |
| DB 연결 설정 | 같은 앱 데이터의 `database_config.json`; password는 OS keychain 우선, view·반출에서 제외 |
| DB 반출 | 앱 데이터의 `database_exports/`; timestamp 스냅샷·SHA-256 manifest |
| 거래·전략·리스크·예산 | 실행 CWD의 `data/`; 시작 로그의 실제 경로 확인 |
| 로그 | 실행 CWD의 `logs/` |
| Discord 설정 | 선택 `secure_config.json`; 실행 CWD 등 코드의 후보 경로에서 로드 |

macOS 앱 데이터는 `~/Library/Application Support/com.countjung.kisautotrade/`, Windows는 `%APPDATA%\com.countjung.kisautotrade\`입니다. 기존 앱 데이터의 `data/`만 존재하면 CWD의 `data/`로 이전을 시도합니다. 이전 실패 시 기존 위치를 계속 사용할 수 있으므로 시작 로그로 실제 경로를 확인합니다. 같은 data 디렉터리의 중복 프로세스는 차단합니다.

프로파일의 비밀키는 암호화 없이 저장됩니다. 비밀 설정·프로파일·DB password·로그를 저장소나 공유 연구 결과에 넣지 않습니다. Discord 선택 설정은 [별도 가이드](discord-setup-guide.md)를 사용합니다.

### 데스크톱 DB 관리

기본은 JSON입니다. Settings → 저장소 관리에서 자동매매를 정지하고 다음 순서로 전환합니다.

1. PostgreSQL 또는 MariaDB 연결 정보·TLS를 저장하고 연결을 테스트합니다.
2. 앱 테이블 생성/업그레이드와 schema 상태를 확인합니다.
3. **JSON → DB 가져오기**를 실행하고 결과를 확인합니다.
4. 조건을 만족한 뒤 **DB 저장 활성화**를 선택합니다.

DB 장애 때 JSON으로 조용히 대체 저장하지 않습니다. DB → JSON 스냅샷 반출과 JSON 저장 전환은 별도 작업입니다. 반출 파일을 현재 data에 자동 복원했다고 가정하지 않습니다. 테이블 비우기·삭제는 DB 비활성 상태 등 조건과 확인 문구를 요구합니다. 프로파일·인증정보·로그는 document 이관 대상이 아닙니다.

TLS `Require`는 인증서 신뢰와 접속 hostname을 모두 검증합니다. 인증서의 이름과 맞는 host를 사용하세요. 서버가 중단되면 연결·읽기·쓰기는 오류를 반환하고 DB 저장 설정을 유지합니다. 서버 복구 후 같은 연결 풀에서 다시 연결할 수 있지만, 실패한 쓰기의 완료 여부는 별도로 확인해야 합니다.

DB 연결 설정 저장이 실패하면 이전 설정 파일과 OS keychain을 함께 복원합니다. 저장이 중단되거나 복원 확인이 실패하면 `database_config.json.recovery` 표시로 연결과 다음 저장, 앱 시작을 차단합니다. 이 경우 설정 파일·백업과 keychain이 같은 접속 대상의 자격증명인지 복구 확인이 필요합니다. 실행 중 앱도 별도 복구 차단 상태를 유지하므로 표시 파일만 삭제해 우회하지 마세요. OS keychain을 사용할 수 없는 환경은 기존의 권한 제한 파일 저장을 유지합니다.

## 9. 데스크톱과 웹 접속

데스크톱은 Tauri IPC, 브라우저는 같은 백엔드의 지원된 REST 경로를 사용합니다. 브라우저만 열거나 Vite만 실행해도 주문 백엔드가 생기는 것은 아닙니다.

1. 데스크톱 앱을 실행하고 Settings → **웹 접속 설정**에서 URL과 `dist/` 상태를 확인합니다. 기본 주소는 `http://localhost:7474`입니다.
2. 개발 환경에서 React 산출물이 필요하면 프로젝트 루트에서 `npm run build:web`을 실행합니다. Settings에서 실제 dist 경로를 맞춥니다.
3. 변경 기능을 사용하려면 데스크톱 Settings에서 32자 이상의 새 웹 API token을 저장하고 재시작합니다.
4. 브라우저 Settings에 **현재 웹 API token**을 입력하고 **세션에 적용**합니다. token은 sessionStorage에 보관되고 변경 요청의 Bearer 인증에 사용합니다.
5. 다른 기기에서 접속하려면 **LAN 공개 허용**을 명시적으로 켜고 재시작한 뒤 해당 컴퓨터의 IP·포트로 접속합니다.

기본 bind는 localhost입니다. LAN 공개 시 GET/HEAD 조회는 API token을 요구하지 않으므로 계좌·로그 등 조회 자료가 네트워크에 노출될 수 있습니다. token은 변경 API를 보호하며, 다른 origin 요청은 거부합니다. 원격 공개가 모든 조회의 인증을 보장하지 않습니다.

웹에서 지원된 주문·프로파일·전략 변경은 token을 요구합니다. **DB 자격증명·연결·이관·테이블 삭제 관리는 데스크톱 전용**이며 임의 SQL을 받지 않습니다. LAN·포트·token 설정은 재시작 전후의 실행 상태와 저장 상태를 구분해 확인합니다.

### 연속 상승/하락의 진입 확인

매수·매도 횟수는 실시간 가격 관측을 세며 일수와 다릅니다. 선택 필터는 최소 누적 변화율, 완료 일봉 ATR 대비 상승폭, 완료 종가 MA 확인이며 각각 0은 사용하지 않습니다. 여러 필터를 켜면 모두 충족해야 신규 매수 신호를 냅니다. 누적 변화와 ATR은 기준 이상, MA는 기준보다 높아야 통과합니다. ATR 0·준비 자료 부족·잘못된 설정은 신규 진입을 보류하며 기존 보유의 연속 하락 매도 조건은 유지합니다.

실시간은 약10초 가격 관측과 별도 갱신하는 완료 일봉을 사용합니다. 연구의 ATR·MA 필터는 일봉에서만 계산하며 현재 평가 봉의 OHLC를 미리 쓰지 않습니다. 준비 표시의 후보·거절·통과는 수량 조절 ATR 및 실제 체결과 다릅니다. 필터를 통과해도 공통 주문 방어·비중·현금·리스크에 의해 차단될 수 있습니다. 현재 요청이나 A/B 기록의 세 필터가 모두 0 또는 누락이면 비활성으로 표시합니다. 활성 필터의 이전 기록에 준비 정보가 없을 때만 준비 정보 없음으로 표시합니다. [사전 고정 후보 비교](research/consecutive-filters-20261018/report.md)를 운용 설정의 자동 추천으로 해석하지 않습니다.


### 모멘텀의 보유 상태와 진입 교차

모멘텀은 비교 관측 수 전 가격 대비 변화율을 사용합니다. 실시간은 약10초 가격 관측이며 연구는 선택 봉 종가이므로 같은 관측 수가 같은 기간을 뜻하지 않습니다. 기본 level은 임계값 이상 상승할 때 미보유 매수, 음수 임계값 이하일 때 보유 매도만 만듭니다. 실제 체결로 확인한 전략 소유 수량을 사용하며 무보유 매도와 이미 보유 중인 추가 매수 신호를 만들지 않습니다.

선택 crossing은 상승 임계값을 아래에서 상향 통과할 때 신규 매수 후보를 만듭니다. 재무장 간격은 상대%가 아닌 **%p**입니다. 임계값5/간격1이면 4 이하를 관측한 뒤 5 이상으로 올라와야 다시 후보가 됩니다. 4와5 사이에서는 기존 후보만 취소됩니다. level에서는 간격이 미사용이지만 초안/저장값은 보존합니다. 두 모드 모두 기존 음수 임계값 보유 청산을 유지합니다.

미체결 후보는 상승 조건 유지 중 재시도할 수 있고, 같은0수량 게시나 다음 시가 대기를 체결로 세지 않습니다. 공통 주문 방어·리스크·pending과 실제 소유 피드백은 계속 적용됩니다. A/B에서 모드·간격 차이를 확인하세요. [생산 비교](research/momentum-feedback-20261020/report.md)는 신호 감소와 손익 개선을 구분하며 crossing·재무장 간격을 운용 기본값으로 추천하지 않습니다.


### 이격도의 실제 보유와 선택 조건

이격도는 현재 가격을 포함한 이동평균 대비 괴리율입니다. 기본은 MA20에서 −5%이하 미보유 매수, +5%이상 보유 매도입니다. 실제 전략 소유 수량을 확인하므로 무보유 매도와 이미 보유한 상태의 추가 매수 후보는 만들지 않습니다.

선택 `crossing`은 이전 이격도가 매수 임계값보다 높다가 현재 임계값 이하가 되는 하향 교차를 확인합니다. 미체결 후보는 조건 유지 중 재시도하며 조건을 벗어나면 취소합니다. 장기 추세 확인은 직전 N가격의 평균보다 현재 가격이 높을 때만 진입합니다. 0은 비활성입니다. 실시간 시작 후에는 실제 이전 관측 N개가 준비되어야 하며, 일봉 준비 자료를 실시간 관측으로 세지 않습니다.

보유 관측 한도와 손절은 각각 0이면 비활성입니다. 관측 한도는 실제 체결 뒤 평가 횟수이며, 실시간 약10초 관측63회와 일봉 연구63봉은 기간이 다릅니다. 기록된 보유 나이는 설정 변경이나 부분 매도로 초기화하지 않습니다. 재시작 원장에서 나이를 확인할 수 없으면 활성 한도는 보수적으로 매도 후보를 만듭니다. 손절은 실제 평균체결가 대비 현재 관측 가격 기준이며 종가 연구에서는 다음 시가에 체결될 수 있습니다. 두 보호 조건은 소유 잔량 전량 매도를 요청하지만 주문 거절·대기·부분체결·가격 갭이 있어 보유 기간이나 손실률을 보장하지 않습니다.

기본 level과 선택 조건의 효과는 [이격도 연구](research/deviation-policy-20261020/report.md)에 구분합니다. 작은 청산 표본과 낮은 투자 비중을 함께 확인하고, 관측 횟수를 거래일이나 체결 신호를 실제 체결로 해석하지 마세요.

설정을 저장하는 동안 새로 편집한 값은 이전 저장 응답 뒤에도 남습니다. 저장 버튼이 다시 활성화되면 이어서 저장할 수 있습니다. 일반 전략·가격조건·LTH에 동일하게 적용하며, 계좌/프로파일을 전환한 뒤 과거 응답이 현재 초안을 지우지 않도록 구분합니다.
